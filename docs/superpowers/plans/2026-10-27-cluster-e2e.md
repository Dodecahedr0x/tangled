# Cluster E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verify the five specified surfaces against isolated local processes and produce reproducible resource benchmarks.

**Architecture:** A test-only `tangled-e2e` workspace package runs actual knot binaries and provider workers, with counted TCP proxies and disk/RSS sampling. Scenario modules use production app cores over HTTP; a CLI runs correctness workloads and release repetitions and writes JSON artifacts.

**Tech Stack:** Rust, Tokio, reqwest, existing app cores, tempfile, serde_json, OS process RSS via `ps`.

**Spec:** `docs/superpowers/specs/2026-10-27-cluster-e2e-design.md` (approved by user).

## Global Constraints

- Preserve pre-existing dirty changes and moved specifications under `docs/spec`.
- Loopback ephemeral ports, temporary data, no external accounts or services.
- Correctness assertions remain enabled in benchmark runs.
- Metrics: logical state bytes, counted TCP application bytes, monotonic processing wall time, sampled RSS with explicit missing-value errors.
- No browser coverage claim; existing vector/unit coverage is explicitly separate.
- Leave work reviewable in the current checkout; no automatic commit of unrelated changes.

## Review Focus

- Startup failure or workload panic must reap child processes and forwarding tasks.
- Zero/invalid CLI workload sizes must fail before reporting successful benchmark results.
- Warmup/readiness traffic must not contaminate measured byte deltas.
- Missing RSS samples must fail or carry an explicit unavailable reason, never masquerade as zero.
- An acceptance feature without a completed scenario must fail the coverage gate.

## Task 1: Cluster harness, metric primitives, and CLI

**Files:** `crates/tangled-e2e/{Cargo.toml,src/lib.rs,src/main.rs,src/cluster.rs,src/metrics.rs,tests/harness.rs}`, root `Cargo.toml`.

**Interfaces:** `Node::knot(root: &Path, name: &str, peers: &[String]) -> anyhow::Result<Node>` and `Node::provider(root: &Path, name: &str) -> anyhow::Result<Node>` are async; public fields `url: String`, `dir: PathBuf`, `identity: Identity`; `Node::restart(&mut self)` async; `Node::pid() -> u32`. `Cluster::start() -> Result<Cluster>` owns `root: TempDir`, `nodes: Vec<Node>` (three knots), and `client: reqwest::Client` (redirects disabled, request timeout). `Node::client() -> KnotClient`, `Node::siws(&Identity) -> Result<KnotClient>` async. `Node` teardown kills/reaps its child and aborts its proxy. Scenarios expose `pub async fn run(cluster: &mut Cluster, operations: usize, payload_bytes: usize) -> anyhow::Result<Vec<&'static str>>`; return IDs only after assertions pass.

- [ ] Write harness tests for exact bidirectional byte counts, file-size deltas, percentile handling, process RSS, invalid workload configuration, coverage omissions, and cleanup on failed readiness.
- [ ] Run the tests before implementation and observe the missing harness failure.
- [ ] Implement proxies, subprocess ownership, persistent restart, provider worker, metrics, and versioned JSON report with per-scenario measurements and repeated-run summaries.
- [ ] Run `cargo test -p tangled-e2e --test harness`; expected all pass.
